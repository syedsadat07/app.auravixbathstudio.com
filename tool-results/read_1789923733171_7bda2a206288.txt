     5→## ARCHITECTURE RULES (READ FIRST)
     6→- **Single page route**: The ONLY page is `src/app/page.tsx` (SPA). All navigation is hash-based client-side views. NEVER create `src/app/*/page.tsx`.
     7→- **Backend = Next.js API routes** under `src/app/api/**/route.ts`. No server actions.
     8→- **Server-side RBAC is mandatory**. Every API route must verify session + role via helpers in `src/lib/auth.ts`. Never trust the client.
     9→- **Quotation pricing is ALWAYS recomputed server-side** from the materials/packages master data. Client sends selections (material IDs + qty), server computes money.
    10→- Passwords hashed with bcryptjs (never plaintext, never returned in API responses).
    11→- Prisma client: `import { db } from '@/lib/db'`. Schema in `prisma/schema.prisma`. SQLite.
    12→- Currency formatting: `formatINR` from `src/lib/format.ts` (Indian grouping, e.g. ₹1,57,500).
    13→- All API responses JSON: success → 200 with payload; error → `{ error: "message" }` with proper status (400/401/403/404/500).
    14→- Use `sonner` toast (`import { toast } from 'sonner'`) — Toaster mounted in layout.
    15→- shadcn/ui components are in `src/components/ui/*` — use them; do not rebuild primitives.
    16→- Brand: primary orange `--primary` (already themed), charcoal header/sidebar `bg-[#232327]`/`#1D1D21`, warm white background. Status badge color helpers in `src/lib/status.ts`.
    17→- Font Inter loaded via layout `<link>`; font-family set in globals.css.

    21→## DOMAINS & CONSTANTS
    22→- Lead statuses: NEW, CONTACTED, CONSULTATION_SCHEDULED, MEETING_DONE, QUOTE_PREPARING, QUOTE_SHARED, FOLLOW_UP, CONVERTED, CLOSED_LOST (+ lostReason: CANCELLED_PLANS, BUDGET, COMPETITOR, NOT_RESPONDING, LOCATION_ISSUE, TIMELINE_ISSUE, OTHER).
    23→- Quote statuses: DRAFT, UNDER_REVIEW, PUBLISHED, QUOTE_SHARED, TC_ACCEPTED, PAYMENT_PENDING, PAYMENT_RECEIVED, ORDER_CONFIRMED, ORDER_FREEZE, EXPIRED, CANCELLED.
    24→- Version types: INITIAL, UPGRADED, REVISED.
    25→- Packages: Basic ₹2,500/sq.ft, Premium ₹3,500/sq.ft, Luxury ₹4,500/sq.ft (DB-driven, Super Admin editable).
    26→- Materials seed: Ceramic Tile ₹65/sq.ft, Vitrified Tile ₹80/sq.ft (AREA rule, wastage %), fixtures/add-ons PIECE rule.
    27→- Bathroom types: MASTER, COMMON, GUEST, ATTACHED, POWDER_ROOM, OTHER.
    28→- Units: sq.ft, sq.m, piece, set, unit, meter, running ft, kg, litre.
    29→- Quantity rules: AREA (qty = ceil(totalArea / coverage × (1+wastage%))), PIECE (qty as entered), FIXED (qty=1).
    30→- Settings keys: company_name, company_address, company_phone, company_email, company_website, gstin, pan, reg_number, quote_prefix (ABS-Q), quote_validity_days (30), gst_rate (18), consultation_fee (299), bank_details, upi_details, terms, orders_target (10), admins_can_publish (false), logo_url.
    31→- Numbering: leadNumber `BEN` + 5-digit seq (BEN00001…, start 1000). quotationNumber `${prefix}-${6-digit seq}` (ABS-Q-000001…, start 245). Version display: `${quotationNumber}-0${versionNumber}`.
    32→- Session: JWT-like HMAC token in httpOnly cookie `abs_session`, 7-day expiry. Helpers in `src/lib/auth.ts`.

    34→## CALCULATION ENGINE (`src/lib/calc.ts` — ALREADY IMPLEMENTED, DO NOT MODIFY)
    35→- `computeBathroomArea(length, width)` → sq.ft
    36→- `calcQuotation({bathrooms:[{length,width}], packageRate, items:[{quantity, rate}], discountType FLAT|PERCENT, discount, gstRate})` → `{ totalArea, packageAmount, itemsAmount, grossValue, discountAmount, taxableValue, gstAmount, totalPayable }`
    37→- grossValue = packageAmount + itemsAmount; taxableValue = grossValue − discountAmount; gst = taxable × gstRate/100; total = taxable + gst. All rounded to 2 decimals.

    44→### Auth (2-a)
    45→- `POST /api/auth/login` `{email, password}` → `{user:{id,name,email,role,mustChangePassword}}`. Sets cookie. 401 on bad creds. Audit-log LOGIN.
    46→- `POST /api/auth/logout` → `{ok:true}`
    47→- `GET /api/auth/me` → `{user}` or 401 `{error}`
    48→- `POST /api/auth/change-password` `{currentPassword,newPassword}` (min 8 chars) → `{ok:true}`; clears mustChangePassword.

    50→### Users — Super Admin only (2-a)

    52→- `POST /api/users` `{name,username,email,mobile?,password,role?'ADMIN'}` → user (201). Audit CREATE_ADMIN.
    53→- `PATCH /api/users/[id]` `{name?,email?,mobile?,status? ACTIVE|DISABLED}` → user. Audit.
    54→- `POST /api/users/[id]/reset-password` → `{temporaryPassword}` (generated, also sets mustChangePassword). Audit.

    57→- `GET /api/leads?tab=all|scheduled|done|closed_lost&search=&adviserId=&from=&to=&mine=1` → `{total, leads:[{id,leadNumber,status,lostReason,createdAt,appointmentDate,customer:{id,name,phone,email,address,city,pincode},assignedAdmin:{id,name},activeQuote:{id,quotationNumber,versionNumber,status,totalPayable,grossValue}|null}]}`. Admins ALWAYS see only their own leads (server-enforced, `assignedAdminId = self`); Super Admin sees all.
    58→- `POST /api/leads` `{customer:{name,phone,email?,address?,city?,pincode?}, appointmentDate?, notes?, source?}` → `{lead}` (creates/reuses customer by phone; assigns adviser = creator). Audit.

   113→### Quotations (2-c) — CORE
   114→- `GET /api/quotations?status=&search=&mine=1` → `{total, quotations:[{id,quotationNumber,versionNumber,versionType,status,totalPayable,grossValue,totalArea,validityDate,createdAt,customer:{id,name,phone},createdBy:{name},bathroomCount}]}` (admin: own only)
   115→- `POST /api/quotations` payload:
   116→```
   117→{ customerId?, leadId?,
   118→  customer?: {name,phone,email?,address?,city?,pincode?},   // create-or-reuse by phone
   119→  bathrooms: [{name,type,length,width,height?}],
   120→  packageId: string,
   121→  selections: {
   122→    tileIds?: [{materialId}],           // AREA-rule materials applied to total area
   123→    fixtures?: [{materialId, quantity}],
   124→    addons?: [{materialId, quantity}],
   125→    consultation?: boolean               // adds consultation_fee as item
   126→  },
   127→  discountType: 'FLAT'|'PERCENT', discount: number,
   128→  notes?: string, publish?: boolean      // publish only if permitted
   129→}
   130→```
   131→→ Server loads materials/packages from DB, computes via calc engine, creates Quotation + QuotationVersion#1 + Bathrooms + Items (each item snapshot name/unit/rate). Returns `{quotation:{id,quotationNumber,versionNumber,...}}`. Audit QUOTE_CREATE.
   132→- `GET /api/quotations/[id]` → `{quotation:{...,currentVersion:{...all fields, bathrooms:[], items:[]}, versions:[{id,versionNumber,versionType,status,totalPayable,createdAt,createdByName}]}}`
   133→- `POST /api/quotations/[id]/versions` same payload as POST (creates versionNumber = max+1, versionType from payload or UPGRADED) → `{quotation}`. Audit QUOTE_VERSION_CREATE. Not allowed if quotation CANCELLED.
   134→- `PATCH /api/quotations/[id]/status` `{status}` — allowed transitions per role (SUPER_ADMIN: any; ADMIN: QUOTE_SHARED/TC_ACCEPTED/PAYMENT_PENDING if admins_can_publish or for non-publish statuses). Sets version status for current version too. Audit QUOTE_STATUS.
   135→- `POST /api/quotations/[id]/publish` → current version PUBLISHED + quotation PUBLISHED. SUPER_ADMIN always; ADMIN only if setting admins_can_publish=true (else 403). Audit QUOTE_PUBLISH.
   136→- `POST /api/quotations/[id]/duplicate` → new draft quotation `...-DUP` copy of current version → `{quotation}`. Audit.
